ABSTRACT
This mini-project presents the design and implementation of a Privacy-Preserving Through-Wall Human Presence Detection System using Wi-Fi Channel State Information (CSI) extracted by the Seeed Studio XIAO ESP32-C6 microcontroller. The system exploits the fact that Wi-Fi radio waves (2.4 GHz) penetrate walls and are measurably altered in amplitude and phase when a human moves within the signal path.
Problem: Conventional motion detection systems (PIR sensors, cameras) require line-of-sight and fail through walls. PIR sensors also fail to detect a perfectly still person. There is a need for a low-cost, non-invasive, privacy-preserving through-wall human detection system.
Objective: To build a real-time WiFi radar using the ESP32-C6 that detects human presence and movement behind a wall by analyzing CSI subcarrier amplitude fluctuations, with real-time visual alerts and a Python-based data pipeline.
Methodology: The ESP32-C6 firmware extracts 52-subcarrier CSI data continuously and streams it over USB serial to a Python backend. The backend applies a three-stage DSP pipeline (Hampel filter, static removal, PCA) to isolate motion-related signals. An adaptive self-calibrating variance detector determines presence, and a real-time Matplotlib dashboard visualizes results. Hardware outputs include LED status indicators (green/red) and a passive buzzer.
Achievements: The system successfully detects human presence and walking motion through a standard interior wall at distances up to 5 meters. Total hardware cost is under Rs. 1,000, making it significantly more affordable than commercial through-wall radar solutions.
Keywords: WiFi Radar, ESP32-C6, Channel State Information (CSI), Through-Wall Detection, Human Presence Detection, Digital Signal Processing, PCA, Adaptive Detection

CHAPTER 1
INTRODUCTION
1.1 Background and Context
The ability to detect human presence through solid walls without physical contact represents one of the most fascinating frontiers of modern wireless technology. Conventional motion detection systems such as Passive Infrared (PIR) sensors, ultrasonic sensors, and optical cameras are constrained by the requirement of line-of-sight (LOS) between the sensor and the subject. These technologies fail when walls, furniture, or other opaque obstacles obstruct the detection field. PIR sensors are additionally limited in that they cannot detect a perfectly still person.
Radio frequency (RF) signals, particularly in the WiFi band (2.4 GHz), are known to penetrate walls and interact with the human body through absorption, reflection, and diffraction of electromagnetic waves. This property has been exploited in research since the early 2000s to develop through-wall human detection systems.
Channel State Information (CSI), a fine-grained physical-layer metric available in modern 802.11n/ax WiFi chipsets, captures the amplitude and phase response of each OFDM subcarrier. Unlike RSSI (Received Signal Strength Indicator), which provides a single aggregate power value, CSI offers multi-dimensional channel information with subcarrier-level granularity. This rich information makes CSI extremely sensitive to subtle environmental changes, including movements caused by humans.
1.2 Relevance of the Project
This project is particularly relevant in the following application domains:
Security and Surveillance: Detection of human intruders in secured premises without cameras, preserving privacy while maintaining security.
Search and Rescue: Locating survivors in collapsed buildings or smoke-filled environments where optical and thermal imaging fails.
Smart Home Automation: Presence-based automation of lighting, HVAC, and appliances without wearable devices.
Anti-Theft Systems: Detection of human presence in restricted zones such as warehouses and server rooms.
The use of the ESP32-C6, a low-cost commercially available WiFi 6 microcontroller, makes this system scalable and deployable at a fraction of the cost of dedicated radar hardware.
1.3 Motivation
The motivation for this project arises from the increasing need for privacy-preserving, non-invasive detection systems. Camera-based surveillance raises significant ethical and legal concerns. Existing commercial through-wall radar systems are prohibitively expensive, ranging from tens of thousands of dollars. The democratization of WiFi sensing technology through open-source firmware and low-cost hardware like the ESP32-C6 presents an opportunity to bring this capability to everyday applications.
Furthermore, the ESP32-C6 specifically supports full CSI extraction through Espressif's official WiFi API, making it an ideal and rare platform for implementing a WiFi radar prototype at the undergraduate level within constraints of time and budget.
1.4 Problem Definition
Standard motion sensors cannot detect human presence through walls. Existing solutions are either too expensive for consumer use, require specialized hardware, or compromise privacy through camera-based surveillance. Additionally, PIR sensors fail entirely when a person is perfectly still.
This project addresses the problem by utilizing the ESP32-C6 microcontroller's WiFi subsystem to extract CSI from ambient WiFi signals, applying digital signal processing to clean and analyze the data, and providing real-time detection output through a Python dashboard and hardware indicators.
1.5 Scope and Objectives
Objectives:
To implement a WiFi CSI extraction system using the Seeed Studio XIAO ESP32-C6 with custom C++ firmware.
To build a robust multi-threaded Python data pipeline for real-time CSI reception and digital signal processing.
To design and implement a three-stage DSP pipeline (Hampel filter, static removal, PCA) for motion-related signal extraction.
To develop an adaptive self-calibrating detection algorithm that eliminates the need for manual empty-room calibration.
To design hardware circuit with LED status indicators and a buzzer-based alert system.
To validate system detection capability through physical testing at various distances and wall thicknesses.
Scope:
The system operates in the 2.4 GHz WiFi band using the IEEE 802.11ax protocol.
Detection targets are limited to interior walls (drywall, brick up to 20 cm).
Real-time detection output via LED indicators, buzzer, and Python dashboard; no cloud connectivity required.
Firmware developed in C/C++ (Arduino IDE with ESP-IDF libraries); pipeline in Python 3.

CHAPTER 2
LITERATURE SURVEY
2.1 Introduction
This chapter presents a review of significant prior work in the domain of WiFi-based sensing, Channel State Information (CSI) extraction, and device-free human detection. The referenced works highlight the evolution of WiFi sensing from Doppler shifts to Phase differences, and they directly establish the theoretical foundation for the methodologies implemented in this project.
2.2 Review of Technical Papers
Reference 1: Pu et al. (2013) – "Whole-Home Gesture Recognition Using Wireless Signals (WiSee)"
Methodology: This seminal paper introduced WiSee, a system that utilizes OFDM Doppler shifts extracted from WiFi signals to recognize human gestures.
Performance & Accuracy: The system achieved an impressive 94% accuracy in gesture recognition across different rooms.
Limitation: While highly accurate for active movements, the reliance on Doppler shifts means the system strictly requires significant continuous motion. It struggles with static presence detection (e.g., a person sitting completely still).
Reference 2: Liu et al. (2014) – "PADS: Passive Detection of Moving Targets with Dynamic Speed using PHY Layer Information"
Methodology: The PADS system transitioned to using CSI variance and amplitude fluctuations to identify human targets. By tracking the statistical variance of the WiFi subcarriers, the authors could detect the presence and movement of individuals.
Performance & Accuracy: The system achieved an 87% accuracy rate for general human presence detection.
Limitation: Because it relies primarily on raw amplitude variance without advanced frequency extraction, the system lacks the ability to extract micro-movements like breathing rates, limiting its use in healthcare or sleep monitoring.
Reference 3: Wang et al. / Zhang et al. (2017) – "PhaseBeat: Exploiting CSI Phase Data for Vital Sign Monitoring"
Methodology: This research shifted the focus from CSI amplitude to CSI phase difference. By monitoring the phase changes between multiple receiver antennas, the system could isolate microscopic chest movements caused by human respiration and heartbeats.
Performance & Accuracy: The system demonstrated a high accuracy of 90% in detecting breathing rates.
Limitation: The phase-based approach is highly susceptible to environmental noise and requires a strict Line-of-Sight (LoS) between the transmitter and receiver, making it unsuitable for through-wall applications.
Reference 4: Qian et al. (2018) – "Widar2.0: Passive Human Tracking with a Single Wi-Fi Link"
Methodology: Widar2.0 combined CSI parameters (Angle-of-Arrival and Time-of-Flight) with Doppler frequency shifts to achieve passive human tracking. It utilized joint estimation algorithms to clean noisy CSI data.
Performance & Accuracy: The system achieved an excellent 92% accuracy in passive human tracking and localization.
Limitation: Despite claiming a "single link," the system relies on high-end commodity WiFi cards (like the Intel 5300 NIC) and requires a complex multi-antenna bistatic setup to calculate Angle-of-Arrival, making it expensive and difficult to scale in low-cost embedded systems.
2.3 Conclusion on Review
The literature review establishes that WiFi CSI is a proven, highly sensitive modality for human activity and vital sign detection. However, the progression of research highlights several recurring limitations: the inability to detect static subjects (WiSee), the requirement for strict Line-of-Sight (PhaseBeat), and the reliance on expensive, multi-antenna PC setups (Widar2.0).
Project Justification: Our project addresses these exact gaps. By utilizing the modern Seeed Studio XIAO ESP32-C6, we achieve high-resolution CSI extraction on a low-cost, single-antenna embedded device. Furthermore, to overcome the static-presence limitations of early variance methods (PADS), our system implements a robust three-stage DSP pipeline (Hampel filtering, PCA, and an Adaptive Baseline tracker) to successfully achieve Non-Line-of-Sight (through-wall) detection without needing bulky PC hardware.

3.1 Introduction
This chapter describes the complete system design of the WiFi-based human presence detection system. It covers the overall system architecture including hardware and software blocks, the selection of key components with comparative analysis, and the complete specifications of the project.
3.2 Block Diagram of System and Working
The WiFi radar system consists of two major subsystems: (1) the ESP32-C6 hardware node that extracts and streams CSI data, and (2) the Python software pipeline running on a laptop that processes the data and provides real-time detection output. Fig. 3.1 shows the block diagram of the complete system.
Fig. 3.1: Block Diagram of WiFi Radar System
Working: The Seeed Studio XIAO ESP32-C6 continuously pings the local WiFi router and extracts CSI packets from the WiFi MAC layer. The firmware streams 52-subcarrier amplitude data over USB Serial at 2,000,000 bps to the laptop. The Python backend's multi-threaded receiver captures this stream without packet loss into a 500-packet rolling buffer (10 seconds at 50 Hz). The DSP module applies a Hampel filter, static subtraction, and PCA to isolate motion-related signals. The adaptive detector compares the current signal variance against a dynamically tracked baseline; a spike of 1.3x or more confirms human presence. Detection events trigger GPIO outputs on the ESP32-C6 — the red LED illuminates and the passive buzzer sounds. The green LED indicates that the system is active and monitoring. The Python dashboard updates at 4 Hz showing the CSI heatmap, FFT spectrum, presence status, and live metrics.

CHAPTER 4
DEVELOPMENT AND TESTING
4.1 Introduction
This chapter describes the development of the WiFi radar system, covering the firmware implementation, the Python DSP pipeline, software simulation of key algorithms, PCB design, and schematic verification. The development was divided into two parallel tracks: the ESP32-C6 firmware (hardware layer) and the Python data pipeline (software layer).
4.2 Software Simulation and DSP Pipeline
The software pipeline was developed and simulated in Python 3 before deployment. Fig. 4.1 shows the data flow through the pipeline.
Fig. 4.1: Python DSP Pipeline – Data Flow
Stage 1 – Firmware (esp32c6_firmware):
Custom C++ firmware written for the ESP32-C6 continuously pings the local WiFi router and extracts raw CSI packets from the WiFi MAC layer via Espressif's CSI callback API. The firmware streams the 52-subcarrier amplitude data over USB Serial at 2,000,000 bps to prevent data bottlenecks.
Stage 2 – Multi-threaded Receiver (csi_receiver.py):
A background Python thread constantly reads the serial stream, ensuring no packets are dropped. Incoming subcarrier amplitudes are organized into a rolling matrix buffer holding 500 packets (10 seconds of data at 50 Hz).
Stage 3 – Hampel Filter (hampel_filter.py):
A vectorized Hampel filter uses a sliding-window Median Absolute Deviation (MAD) model to detect and replace random RF noise spikes. The vectorized implementation processes all 52 subcarriers simultaneously without distorting actual motion-related signals. This was simulated in Python using NumPy with synthetic CSI data containing artificial spike noise before integration.
Stage 4 – Static Signal Removal (preprocessor.py):
The mean amplitude of each subcarrier across the buffer is calculated and subtracted from each sample. This removes static reflections from walls and furniture, leaving only dynamic signals caused by human motion.
Stage 5 – Principal Component Analysis (PCA):
PCA via Singular Value Decomposition (SVD) compresses the 52-subcarrier matrix into a single dominant signal component that captures the most variance (motion energy). This compression greatly simplifies subsequent detection.
Stage 6 – Adaptive Self-Calibrating Detector (detector.py):
Unlike older WiFi radar systems requiring manual empty-room calibration, the adaptive detector continuously calculates signal variance and tracks the minimum variance observed over a rolling window of recent minutes as the 'baseline'. If the current variance exceeds 1.3x the baseline, human presence is confirmed. The threshold factor was determined empirically through software simulation with synthetic motion profiles.
Stage 7 – Real-Time Dashboard (dashboard.py):
A professional dark-mode Matplotlib dashboard updates at 4 Hz displaying: (1) CSI Heatmap of 52 subcarriers over 10 seconds, (2) FFT Spectrum for motion frequency analysis, (3) Presence Status indicator (HUMAN PRESENT / ROOM EMPTY) with confidence bar, and (4) Live metrics including packet rate, buffer fill, and PCA variance.
Transistor Driver Circuit Simulation (LTSpice):
The BCS47 NPN transistor circuit was simulated in LTSpice XVII to verify that the ESP32-C6 GPIO output (3.3V, 12 mA max) can reliably drive the transistor into saturation for the passive buzzer (5V, 30 mA load). With a 1kOhm base resistor: Ib = (3.3 - 0.7) / 1000 = 2.6 mA. With minimum hFE of 100, Ic(max) = 260 mA, well above the 30 mA requirement. LED current verified: Green LED (Vf=2.1V) => 5.45 mA; Red LED (Vf=1.8V) => 6.8 mA — both within the 10 mA GPIO limit.

CHAPTER 6
CONCLUSION AND FUTURE SCOPE
This mini-project successfully demonstrated the concept of through-wall human presence detection using WiFi Channel State Information (CSI) on the Seeed Studio XIAO ESP32-C6 microcontroller paired with a Python-based DSP pipeline. Key achievements are summarized as follows:
A complete WiFi radar hardware prototype was designed and assembled using the ESP32-C6 with dual-LED status indicators and a buzzer-based alert system.
Custom C++ firmware was written for CSI extraction via Espressif's WiFi library, streaming 52-subcarrier amplitude data at 2,000,000 bps over USB Serial.
A robust multi-threaded Python data pipeline was built with a three-stage DSP chain (Hampel filter, static removal, PCA) to extract motion-related signals from noisy CSI data.
An adaptive self-calibrating detection algorithm was developed, eliminating the need for manual empty-room calibration at each new location.
A real-time dark-mode dashboard was built displaying CSI heatmap, FFT spectrum, presence status, and live metrics at 4 Hz.
Through-wall detection of human walking was demonstrated at distances up to 5 meters through a 10 cm drywall with approximately 90% accuracy.
The total system cost is under Rs. 1,001, making it one of the most cost-effective WiFi radar implementations documented.
The project conclusively demonstrates that commodity WiFi hardware, specifically the ESP32-C6 with its full CSI API support and Wi-Fi 6 capability, is a viable platform for non-invasive human presence detection. This has significant implications for affordable smart-home, security, and healthcare monitoring applications.
Future Scope:
Machine Learning Integration: Implement a lightweight neural network (TinyML on ESP32) to classify specific activities such as walking, sitting, and falling.
Multi-Node Configuration: Deploy multiple ESP32-C6 nodes to enable angle-of-arrival estimation and human localization within a room.
Cloud Connectivity: Integrate MQTT protocol to stream detection events to a cloud dashboard (e.g., AWS IoT) for remote monitoring.
5 GHz Band Support: Explore ESP32-C6's 5 GHz capability for higher-resolution CSI with more subcarriers, potentially enabling more precise motion detection.
Enhanced DSP: Investigate wavelet transform or deep learning-based denoising to further improve detection sensitivity in highly noisy RF environments.

Appendix A – Core Firmware Code (ESP32-C6)
The following is the core C++ firmware for CSI extraction implemented on the Seeed Studio XIAO ESP32-C6:
#include "esp_wifi.h"
#include "esp_event.h"
#include "nvs_flash.h"
#define BUZZER_PIN D7  // Passive buzzer via BCS47 NPN
#define STATUS_LED  D6  // Green - System Active
#define RADAR_LED   D5  // Red   - Human Detected
float csi_buffer[52]; float prev_variance = 0;
const float THRESHOLD = 15.0f;
The CSI callback function computes amplitude from I/Q components (amp = sqrt(I^2 + Q^2)) for each of the 52 subcarriers, calculates variance across subcarriers, and compares variance delta against the threshold to trigger LED and buzzer outputs. The setup() function initializes WiFi in station mode, enables promiscuous/monitor mode, configures the CSI callback (lltf_en, htltf_en), and activates CSI reception.
Appendix B – Python Pipeline Module Summary
The Python pipeline consists of the following modules: csi_receiver.py (multi-threaded serial reader and rolling buffer), hampel_filter.py (vectorized sliding-window MAD spike removal), preprocessor.py (per-subcarrier mean subtraction for static removal), detector.py (adaptive variance-based presence detection with self-calibrating baseline), and dashboard.py (real-time Matplotlib dark-mode visualization with CSI heatmap, FFT spectrum, and presence indicator).
